# Letterboxed Gamez

A premium, original, responsive daily word-puzzle game — Next.js App Router,
TypeScript, Tailwind CSS v4. Warm ivory, deep forest green, editorial
typography, and a board built to be read at a glance.

## Play

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm run start
```

## Rules (enforced in `src/lib/game.ts`)

1. Words need at least 3 letters; each letter at most once per word.
2. No two consecutive letters from the same side.
3. Each word after the first starts with the previous word's last letter.
4. Words must be in the curated dictionary.
5. Use all 12 letters to solve.

## Puzzle verification — no unverified claims

Every puzzle in `src/lib/puzzles.ts` carries a stored solution. Before a
puzzle ships, this check must pass:

```bash
npm run verify:puzzles
```

It confirms, for every puzzle: 12 distinct letters (3 per side), every
solution word in the dictionary, no consecutive letters sharing a side,
correct chaining, and all 12 letters covered. The dictionary is a curated
list of common words (~2,800 entries, listed in the open in
`src/lib/dictionary.ts`) — it is not a complete English dictionary, and the
game says so in the UI when a word is not recognised.

## Daily puzzle reset — Pakistan midnight

The daily puzzle is chosen by the calendar date in `Asia/Karachi`
(00:00 PKT, 19:00 UTC the previous day). The selection logic lives in
`src/lib/daily.ts` (`DAILY_TIMEZONE = "Asia/Karachi"`); it uses
`Intl.DateTimeFormat` with that timezone and falls back to the fixed
UTC+05:00 offset if `Intl` is unavailable. Pakistan has no daylight
saving, so both paths agree.

Boundary behaviour is tested in `scripts/daily.test.mjs` (run with
`npm test` or `npm run test:daily`): the puzzle must not change at
18:59:59 UTC, must change at exactly 19:00:00 UTC, must stay the
same for two instants on the same Karachi day, and must advance one
step in the rotation on the next Karachi day. See `src/lib/daily.ts`
for the full list.

## Design and game features

The game was redesigned 2026-10-28 after the owner found the first
design too simple and the colours unconvincing: a deep-forest board
inside a gold frame, cream gradient tiles, a glowing gold word path,
a forest-and-gold masthead with live timer/par/streak chips, and
gold-accented cards throughout. Sides are still distinguished by
name, shape and pattern, never colour alone. After a readability
review (2026-10-28), board tiles were made larger with their side
labels fully inside the tile, unavailable letters use a readable
muted-green tile instead of fading out, the current word is shown
in gold tiles with dark letters, and found words use dark green
text on white — the same fixes were applied to the preview, where
a stylesheet bug had made unpicked tiles nearly invisible.

Features beyond the original brief: a solve timer (starts on the
first picked letter, fastest solve kept in local statistics), a
star rating against par (the stored solution's word count), a
"Choose a puzzle" picker for all seven boards as practice, an
emoji share text (star rating, time, and one side-glyph row per
word), a live countdown to the next daily puzzle at midnight
Pakistan time, and a confetti win celebration that honours
`prefers-reduced-motion`. The in-chat preview
(`preview/letterboxed-preview.html`, regenerated by
`scripts/build-preview.mjs`) carries the same board colours.

## SEO — data-backed, from the Ahrefs export

Editable metadata lives in `src/lib/site.ts` and each page's `metadata`
export, with canonical URLs via `canonical()`. The sitemap (`src/app/sitemap.ts`),
`robots.txt` (`src/app/robots.ts`), Open Graph image (`src/app/opengraph-image.tsx`),
manifest, FAQ structured data and WebApplication structured data are all
generated from that config. Pages: `/`, `/how-to-play`, `/strategies`,
`/hints`, `/faq`, `/about`, `/privacy-policy`, `/terms`.

The keyword strategy is built from the Ahrefs competitor export
supplied by the owner (`letter boxed.csv`, verbatim copy at
`docs/ahrefs-letter-boxed-export.csv`, 208 keywords, parsed and
classified by `scripts/analyze-ahrefs.mjs` into
`docs/ahrefs-classified.csv`). Headline finding: **99.3% of the
reported volume (171,170) is branded, trademark-sensitive, or
typos** — only 29 keywords (1,230 volume) are generic format
phrases. The export has no keyword-difficulty or URL column, so
feasibility is judged only from the competitor's average position
plus relevance; no ranking is promised. Consequences, implemented
and recorded in `docs/seo-keyword-map.md`:

- No page targets a branded term ("letter boxed", "letterboxed",
  NYT / New York Times, Letterboxd, Wordle), a typo, or a
  daily-answer/archive term. No daily solutions are published.
- The generic phrases map to the existing homepage and How to
  Play page only. Strategies and Hints have zero keywords in the
  export and are kept as player-value pages with no keyword-driven
  copy added.
- No new content page is recommended from this data. The one
  copy change made from the export is a single generic phrase in
  the homepage intro ("letter-box word puzzle").
- See `docs/seo-keyword-map.md` for the full page-to-keyword map
  with figures, the brand/intent totals, the audit, and what is
  still missing (Search Console and Core Web Vitals after launch).

## Accessibility

- Tiles are real buttons with letter + side labels; visible focus everywhere.
- Sides are distinguished by name, shape and pattern — never colour alone.
- `prefers-reduced-motion` is honoured; progress is a real `progressbar`
  with text equivalents for used / remaining letters.
- Keyboard: type letters, Enter to submit, Backspace to undo, Esc to clear.
- Mobile-first, large touch targets, no horizontal overflow
  (`overflow-x-clip` on the homepage shell; board max-width 540px).

## Deployment

Deploy as a standard Next.js app (Vercel, or `next build` + `next start`
anywhere Node 20+ runs). Set the production domain in `src/lib/site.ts`
(`SITE.url`) — it is already `https://letterboxedgamez.com`.
